# 1. Purpose

This document is the official AI Build Specification for the AQRuntime project.

Its purpose is to orchestrate AI-assisted software construction by selecting a documentation baseline and enforcing software engineering rules.

This document SHALL NOT contain software specifications.

Software specifications are stored exclusively inside the selected Documentation Baseline.

# 6. Required Documents

The AI SHALL read every markdown document contained inside the selected Documentation Baseline.

Required documents:

- README.md
- MANIFEST.md
- REQUIREMENTS.md
- DESIGN.md
- DATABASE.md

- IMPLEMENTATION.md
- TESTING.md

---

# 7. Scope Policy

The AI SHALL implement only what has been explicitly documented.

The AI SHALL NOT redesign the architecture.

The AI SHALL NOT expand project scope.

The AI SHALL NOT introduce undocumented features.

---

# 8. Conflict Resolution

If documentation contains inconsistencies:

- Stop implementation.
- Report the conflict.
- Request clarification.

Do not guess.

---

# 9. Forbidden Actions

Do NOT:

- redesign architecture
- rename documented components
- modify documentation
- introduce additional modules
- introduce undocumented features
- remove documented functionality
- ignore acceptance tests

---

# 10. Self Review Checklist

Before completing implementation verify:

□ Requirements Coverage

□ Architecture Consistency

□ Storage Consistency

□ CLI Consistency

□ Documentation Consistency

□ Acceptance Test Coverage

---

# 11. Deliverables

The generated implementation shall include:

- Source Code
- Project Structure
- Configuration Files
- Executable CLI
- Tests
- Build Instructions

---

# 12. Completion Criteria

Implementation is complete only when:

✓ Every requirement has been implemented.

✓ Every acceptance test passes.

✓ The project builds successfully.

✓ The runtime executes successfully.

✓ No undocumented feature has been added.

---

# 13. Engineering Constitution

Rule 1

Documentation is the highest authority.

Rule 2

Implementation follows documentation.

Rule 3

Testing validates implementation.

Rule 4

Documentation Baselines are immutable.

Rule 5

Every evolution creates a new Documentation Baseline.

Rule 6

Never modify completed Documentation Baselines.

Rule 7

Generated source code is replaceable.

Rule 8

Documentation is the permanent engineering asset.

---
